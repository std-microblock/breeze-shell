# Breeze Shell — Agent Guide

**Windows 10/11 context menu replacement.** Injected as `shell.dll` into `explorer.exe` (and other file managers). Built with xmake + clang-cl. Windows-only.

## Build & Run

```bash
# Build injector + shell DLL (order matters: inject first)
xmake b inject
xmake b shell

# Or just type xmake to build all targets

# Reconfigure (clean slate) then build
xmake f --toolchain=clang-cl -m releasedbg -y -c
xmake b --yes inject
xmake b --yes shell

# Run — inject shell.dll into processes
xmake r inject

# ASan test build & run
xmake f --toolchain=clang-cl -m releasedbg -y --asan=y -c
xmake r --yes -v asan_test

# Taskbar (rundll32 mode)
xmake r shell taskbar -- -taskbar

# Run single test target (ui_test)
xmake r ui_test
```

## Key Targets (xmake.lua)

| Target | Type | Output | Purpose |
|--------|------|--------|---------|
| `inject` | binary | `breeze.exe` | Injects shell.dll into processes |
| `shell` | shared lib | `shell.dll` | Main context menu logic |
| `asan_test` | binary | `asan_test.exe` | AddressSanitizer test harness |
| `ui_test` | binary | — | UI integration test |

## Architecture

- **Entrypoint**: `DllMain` in `src/shell/entry.cc:218` — dispatches to `mb_shell::main()` based on process name (explorer.exe, onecommander.exe, rundll32.exe, asan_test.exe)
- **Injection flow**: `breeze.exe` (`src/inject/inject.cc`) loads `shell.dll` into target processes via DLL injection + task scheduler
- **Hook system**: `blook` library for inline hooking; all hooks uninstalled on `DLL_PROCESS_DETACH` (`hook_registry::uninstall_all()`) to prevent crash on DLL unload
- **Script engine**: QuickJS (`breeze-js`) with bindings auto-generated from `binding_types.hpp` → `binding_types.d.ts` via `breeze-bindgen`
- **TypeScript UI**: `src/shell/script/ts/` → esbuild bundle → `src/shell/script/script.js` (embedded in binary at compile time via `utils.bin2obj`)
- **Config**: `%USERPROFILE%/.breeze-shell/config.json` — hot-reloaded via file watcher; VSCode users add `$schema` from `resources/schema.json`
- **CI**: `.github/workflows/xmake.yml` — Windows 2025, clang-cl, releasedbg, builds inject + shell

## Generated Files — DO NOT EDIT

- `src/shell/script/script.js` — built from `src/shell/script/ts/`, regenerate with `yarn build` in that dir
- `src/shell/script/binding_types.d.ts` — generated by bindgen, run `scripts/bindgen.bat`
- `src/shell/build_info.h` — generated from `.in` template by xmake `on_config` (git hash, branch, build time)

## Dev Workflow

```bash
# Format all C++ sources
pwsh scripts/reformat.ps1

# Rebuild TypeScript UI
cd src/shell/script/ts && yarn build

# Regenerate JS bindings
scripts/bindgen.bat
```

## Notable Conventions

- C++26 (clangd), C++2b (build), C11 — `set_languages("c++2b", "c11")`
- Clang-cl toolchain required in CI (`xmake f --toolchain=clang-cl`)
- Sentry crash reporting (breakpad backend) — PDB upload in CI
- Font defaults: Segoe UI (main), MS YaHei (fallback), Consolas (mono)
- PS1 scripts under `scripts/` for rebuild/taskbar/asan workflows
- xmake plugin `compile_commands.autoupdate` outputs to `build/`

## Scripting (JS Plugin API)

Plugins go in `%USERPROFILE%/.breeze-shell/scripts/` and are auto-loaded/reloaded by the file watcher in `src/shell/script/`. API bindings documented in `src/shell/script/binding_types.d.ts` (module `mshell`).
