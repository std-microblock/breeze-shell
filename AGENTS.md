# Breeze Shell — Agent Guide

**Windows 10/11 context menu replacement.** Injected as `shell.dll` into `explorer.exe` (and other file managers). Built with xmake + clang-cl. Windows-only.

## Build & Run

```bash
# Build both targets (order: inject first, shell second)
xmake b inject && xmake b shell

# Full reconfigure + build
xmake f --toolchain=clang-cl -m releasedbg -y -c && xmake b --yes inject && xmake b --yes shell

# Run — inject shell.dll into processes
xmake r inject

# ASan test
xmake f --toolchain=clang-cl -m releasedbg -y --asan=y -c && xmake r --yes -v asan_test

# Taskbar (rundll32 mode)
xmake r shell taskbar -- -taskbar

# UI integration test
xmake r ui_test
```

## Architecture

- **Entrypoint**: `DllMain` in `src/shell/entry.cc:218` — dispatches to `mb_shell::main()` based on process name (explorer.exe, onecommander.exe, rundll32.exe, asan_test.exe)
- **Injection**: `breeze.exe` (`src/inject/inject.cc`) loads `shell.dll` via DLL injection + task scheduler
- **Hook system**: `blook` library for inline hooking; all hooks uninstalled on `DLL_PROCESS_DETACH` via `hook_registry::uninstall_all()`
- **Three hook sites for context menus** (all in `src/shell/contextmenu/hooks.cc`):
  1. `NtUserTrackPopupMenuEx` — system menu creation (win32u.dll)
  2. `SHCreateDefaultContextMenu` — OneCommander path (shell32.dll)
  3. `GetUIObjectOf` — OneCommander path (IShellFolder vtable)
- **An identical pattern** runs at all three sites: DWM guard → reentrancy guard → `CreatePopupMenu` → `QueryContextMenu` → `construct_with_hmenu` → `track_popup_menu` → `InvokeCommand`
- **UI stack**: NanoVG rendering via `breeze_ui` library (cross-platform, animation-friendly)
- **Script engine**: QuickJS (`breeze-js`), bindings auto-generated from `binding_types.hpp` → `binding_types.d.ts`

## Generated Files — DO NOT EDIT

- `src/shell/script/script.js` — built from `src/shell/script/ts/`, regenerate with `yarn build` in that dir
- `src/shell/script/binding_types.d.ts` — generated by bindgen, run `scripts/bindgen.bat`
- `src/shell/build_info.h` — generated from `.in` template by xmake `on_config`

## Critical Hook Patterns (hooks.cc)

**All three hook sites must be updated together.** Every change to guards, flags, or menu construction logic must be mirrored across:
1. `install_NtUserTrackPopupMenuEx_hook` — the main entry
2. `install_SHCreateDefaultContextMenu_hook` — OneCommander shell32 path
3. `install_GetUIObjectOf_hook` — OneCommander IShellFolder path

**Reentrancy guard** (`current_live_menu_handle`): Must be set **before** `construct_with_hmenu` (which sends `WM_INITMENUPOPUP`), not just inside `track_popup_menu`'s `live_menu_guard` (which runs on the renderer thread). The guard's destructor clears it when the menu loop exits.

**`live_menu_guard`** (in `track_popup_menu`, renderer thread): Always sets and clears `current_live_menu_handle` and `active_root_menu_widget`. The calling thread's guard is set before `construct_with_hmenu` and the renderer guard redundantly re-sets it (same value, harmless).

**DWM guard**: Check `DwmIsCompositionEnabled()` before any Breeze menu creation — prevents crash on sleep resume.

**`close_next_create_window_exw_window`**: Single shared `atomic_bool` (file-scope, not per-function). Always cleared after checking in `CreateWindowExW` hook. Controls OneCommander window suppression after menu commands.

**IContextMenu2 vs IContextMenu3**: Query for v3 first, fall back to v2. Some shell extensions (Notepad++) implement only `IContextMenu3`. Call `HandleMenuMsg2(message, wParam, lParam, NULL)` for v3.

## Conventions & Gotchas

- `menu_render::current` (`std::optional<menu_render*>`) can be `nullopt` when action callbacks fire — always guard with `if (!current_render || !*current_render) return;`
- `std::optional<Pointer>::operator->()` has UB when empty — always check `has_value()` first before `->range_size()` (applies to `fix_win11_menu.cc` find_upwards results)
- Win10 acrylic: uses `SetWindowCompositionAttribute(ACCENT_ENABLE_ACRYLICBLURBEHIND)` loaded dynamically via `GetProcAddress`; `rect_widget` with tint color instead of `acrylic_background_widget`
- Menu item icon extraction from `dwItemData` uses hardcoded HBITMAP offsets `{0x018, 0x220, 0x020, 0x000, 0x010, 0x030, 0x040}` — fragile across Windows versions
- `sync_native_menu_item_update` defers state sync to renderer thread via `post_loop_thread_task`; widget may not exist yet if task runs during initial construction (safe: logs warning and returns)
- `GetUIObjectOf` hook on OneCommander: found via disassembly of `functionToGetGetUIObjectOfVptr` at `hooks.cc:900-905`
- `flatten_open_with_submenu` config option promotes submenu items to parent level; uses wID matching against "open with" / "打开方式"

## Known Bug Patterns

- Action callback without `menu_render::current` guard → `std::bad_optional_access` → menu never closes
- `current_live_menu_handle` not set before `WM_INITMENUPOPUP` → reentrancy bypass during message processing
- Per-function static flags (OneCommander window suppression) shadow each other when in different hook functions
- GDI handle leak: `getBitmapFromOwnerDraw` needs `DeleteDC(memDC)` + `ReleaseDC(hwnd, hdc)` on all paths
- Direction clamping: `calculate_position` can push menu to opposite side of anchor; direction must be re-derived after clamping
